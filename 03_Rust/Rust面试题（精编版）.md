## 一、语言特性与生态

**Q1. Rust 相比 C++ / Go 的核心优势是什么？**
在**无 GC** 的前提下于**编译期**保证内存安全与线程安全（所有权 + 借用检查 + `Send/Sync`），并提供零成本抽象。相比 Go 无 GC 停顿、表达力更强；相比 C++ 默认安全、无需手动管理内存。

**Q2. Rust 如何做到没有 GC 却内存安全？**
每个值有唯一所有者，离开作用域自动 `drop`；借用检查器保证引用始终有效、无数据竞争。确定性析构 + 编译期检查替代运行时回收。

**Q3. Rust 的编译为什么慢？**
泛型**单态化**为每个具体类型生成代码、trait 解析/借用检查复杂、LLVM 优化重。缓解：用 `cargo check` 快速迭代、拆分 crate、开启增量编译、并行 codegen。

**Q4. edition（版次）是什么？和编译器版本关系？**
Edition 是语法档位（2015/2018/2021/2024），不同 crate 可用不同 Edition 混编；由 `Cargo.toml` 的 `edition` 指定，与 `rustc` 版本相互独立。

**Q5. Rust 适合哪些场景？不适合哪些？**
适合：系统/基础设施、网络服务、CLI、嵌入式、WASM、高性能中间件。不特别适合：快速原型、极重 GC 生态/反射的领域、团队上手成本敏感的项目。

## 二、所有权 / 借用 / 生命周期

**Q6. 说出所有权的三条规则。**
1）每个值有唯一所有者；2）同一时刻只有一个所有者；3）所有者离开作用域时值被 `drop`。

**Q7. move、copy、clone 的区别？**
`move` 转移所有权（源失效）；`Copy` 类型赋值是按位复制、源仍有效（仅无堆所有权的简单类型）；`clone` 显式深拷贝（如 `String` 复制堆数据）。`Copy: Clone`，反之不然。

**Q8. 什么时候会发生 move？**
赋值、传参、返回值、放入集合、被 `move` 闭包捕获等，凡涉及所有权转移的场合。`Copy` 类型除外。

**Q9. 借用规则是什么？为什么限制「一个可变引用或任意多个不可变引用」？**
同一时刻要么一个 `&mut T`，要么任意多个 `&T`，不能并存；引用必须有效。该规则排除数据竞争：读共享、写独占，编译期即可判定。

**Q10. 什么是 NLL（非词法生命周期）？**
自 Edition 2018 起，借用的有效范围按「最后一次使用」计算，而不是整个作用域末尾，从而减少不必要的借用冲突。

**Q11. 生命周期注解会延长数据寿命吗？**
不会。它只描述多个引用间的存活关系，供借用检查器验证，不改变实际生命周期。

**Q12. 生命周期省略的三条规则？**
1）每个输入引用各分配一个生命周期参数；2）只有一个输入生命周期时，赋给所有输出；3）有多个输入但其中含 `&self/&mut self` 时，`self` 的生命周期赋给所有输出。

**Q13. `'static` 是什么？**
表示引用可存活整个程序运行期；字符串字面量是 `&'static str`。注意别用它硬凑编译通过。

**Q14. 为什么 `fn dangle() -> &String { let s = String::new(); &s }` 编译失败？**
返回了指向局部变量的引用，函数结束时 `s` 被释放，产生悬垂引用。应返回 `String`（转移所有权）。

**Q15. 结构体持有引用需要注意什么？**
结构体需带生命周期参数，例如 `struct P<'a> { s: &'a str }`，其生命周期不能短于所借数据。

## 三、类型系统与 Trait

**Q16. 泛型的实现机制？与 Java 泛型有何不同？**
Rust 泛型是**单态化**（编译期为每个具体类型生成专用代码，零运行时开销，代价是代码膨胀）；Java 是**类型擦除**（运行时无泛型信息，装箱/反射）。

**Q17. Trait 与 interface 的区别？**
Trait 可为方法提供默认实现、关联类型、泛型方法与 supertrait；可为外部类型实现外部 trait（受孤儿规则约束）。interface 无默认实现（Java 8 有 default）。

**Q18. 静态分发与动态分发？如何选择？**
泛型/`impl Trait` 静态分发（单态化、无开销）；`dyn Trait` 动态分发（虚表、运行时查找），适合异构集合或减少泛型爆炸。性能优先静态，灵活/编译体积优先动态。

**Q19. 什么是对象安全（object safety）？**
Trait 能作为 `dyn Trait` 的条件：方法不能返回 `Self`、不能含泛型参数、`Self: Sized` 约束的方法除外等。不满足则不能用 trait 对象。

**Q20. `impl Trait` 在参数位置和返回位置含义一样吗？**
不一样。参数位置 `fn f(x: impl Trait)` 是匿名泛型参数（调用方决定具体类型）；返回位置 `fn f() -> impl Trait` 是「某个具体但隐藏的类型」（被调用方决定）。

**Q21. `where` 子句与 trait bound 的作用？**
约束泛型必须实现某些 trait；`where` 写法在约束多时更清晰，也便于表达关联类型约束 `T::Item: Debug`。

**Q22. newtype 模式有什么用？**
`struct Meters(u32)` 用元组结构封装底层类型，实现类型安全（防止单位/含义混用）、为外部类型增加方法、绕过孤儿规则。

## 四、集合与字符串

**Q23. `String` 与 `&str` 的区别？函数参数用哪个？**
`String` 拥有所有权、可增长（堆）；`&str` 是借用的字符串切片。参数优先 `&str`（`String` 可自动解引用为 `&str`，更通用）。

**Q24. 为什么 `String` 不能用整数下标索引？**
字符串是 UTF-8 变长编码，按字节下标可能切在字符中间。应使用 `chars()`/`bytes()` 或切片（须在字符边界，否则 panic）。

**Q25. `Vec<T>` 的 `get` 与 `[]` 索引区别？**
`v.get(i)` 返回 `Option<&T>`（越界为 `None`，安全）；`v[i]` 越界会 panic。

**Q26. `HashMap` 使用注意？**
key 需 `Eq + Hash`；`entry` API 可避免「先查后插」两次查找；默认随机哈希种子防 HashDoS。

**Q27. 数组、切片、Vec 的区别？**
数组 `[T; N]`：编译期固定长度、栈上；切片 `&[T]`：对连续内存的借用视图；`Vec<T>`：可增长的堆分配动态数组。

## 五、错误处理

**Q28. `panic!` 与 `Result` 如何取舍？**
不可恢复/违反程序不变量的错误用 `panic!`；可预期、可恢复的错误用 `Result` 传播。

**Q29. `?` 运算符做了什么？**
若为 `Err(e)` 则提前 `return Err(From::from(e))`（自动错误类型转换）；若为 `Ok(v)` 则解包为 `v` 继续。可用于返回 `Result`/`Option` 的函数。

**Q30. 为什么库代码不应随意 `unwrap()`？**
`unwrap/expect` 遇错会 panic，把可恢复错误变成崩溃，且把决定权丢给库内部。库应返回具体错误类型（常用 `thiserror`），应用层用 `anyhow` 附加上下文。

**Q31. `Box<dyn Error>` 作为返回错误类型有什么特点？**
可吞下任意实现了 `std::error::Error` 的错误，写法简单；但丢失具体类型、需动态分发。大型项目更倾向自定义错误枚举或 `anyhow`。

**Q32. `thiserror` 与 `anyhow` 的分工？**
`thiserror`：为库定义结构化错误枚举（`#[derive(Error)]`）；`anyhow`：应用层快速传播并附加上下文（`context`/`with_context`）。

## 六、智能指针与内部可变性

**Q33. `Box` / `Rc` / `Arc` 的区别与使用场景？**
`Box<T>` 独占堆分配（递归类型、`Box<dyn Trait>`）；`Rc<T>` 单线程共享引用计数；`Arc<T>` 原子引用计数、可跨线程。

**Q34. `Rc` 为什么不能跨线程？**
`Rc` 的计数非原子操作，多线程同时增删会数据竞争，故未实现 `Send/Sync`；跨线程用 `Arc`。

**Q35. `RefCell<T>` 与 `Cell<T>` 的区别？**
都提供内部可变性。`RefCell` 通过 `borrow/borrow_mut` 在**运行时**检查借用规则（违规 panic）；`Cell` 用 `get/set/replace` 整体读写 `Copy` 值，无借用引用。

**Q36. 什么是内部可变性？常见类型？**
通过 `&self` 修改内部数据的模式，用于「外部不可变、内部需可变」的场景。常见：`Cell`、`RefCell`、`Mutex`、`RwLock`、`Atomic*`。

**Q37. `Rc<RefCell<T>>` 为什么常见？有什么风险？**
实现多所有者 + 可变的共享结构（如图/树）。风险：运行时借用冲突 panic、`Rc` 循环引用导致内存泄漏（用 `Weak` 打破环）。

**Q38. `Deref` 与 `Drop` 的作用？**
`Deref/DerefMut` 让智能指针像引用一样被解引用（并支持自动解引用）；`Drop` 定义值离开作用域时的清理逻辑。

## 七、并发

**Q39. `Send` 与 `Sync` 的区别？**
`Send`：值的**所有权**可跨线程转移；`Sync`：值的**共享引用 `&T`** 可跨线程安全共享（即 `&T: Send`）。二者是自动推导的标记 trait。

**Q40. 为什么说 Rust 是「无畏并发」？**
数据竞争被 `Send/Sync` 约束在编译期拦截；共享可变状态需显式用 `Mutex/RwLock` 等同步原语，无法「意外」共享可变数据。

**Q41. channel 与共享内存两种并发模型？**
channel（`mpsc`）通过消息传递转移所有权，天然避免共享；共享状态用 `Arc<Mutex<T>>` 等同步原语。前者解耦、后者适合频繁读写。

**Q42. `Arc<Mutex<T>>` 中锁的注意事项？**
`MutexGuard` 离开作用域自动解锁；注意锁粒度、避免死锁、避免持锁跨 `.await`（用 `tokio::sync::Mutex` 或缩小临界区）。

**Q43. `Mutex` 中毒（poison）是什么？**
持锁线程 panic 会让互斥量进入「中毒」状态，后续 `lock()` 返回 `Err`，提醒数据可能不一致；可 `into_inner` 处理或忽略。

## 八、异步

**Q44. `async fn` 返回什么？Future 是惰性的吗？**
返回一个实现 `Future` 的匿名类型；Future 是**惰性**的，必须被 executor 轮询（`.await` 或提交给运行时）才会推进。

**Q45. 为什么 Rust 标准库不内置异步运行时？**
保持 std 精简、运行时可插拔（Tokio/async-std/smol 各有取舍）。async 语法在语言层，执行器在生态层。

**Q46. `Pin` 解决什么问题？**
许多 Future 是自引用的，移动会导致内部指针失效；`Pin<P>` 保证被指向对象地址固定，是安全实现自引用 Future 的基础。

**Q47. async 与多线程如何选型？**
CPU 密集/少量并发用线程（或 rayon）；高并发 I/O 用 async（Tokio）。注意：不要在 async 任务里做阻塞调用，用 `spawn_blocking`。

**Q48. `.await` 会阻塞线程吗？**
不会。它挂起当前任务并让出执行权给 executor，线程可继续运行其他任务；真正的阻塞（如 `std::thread::sleep`、同步 IO）才会堵住线程。

## 九、工程化与 Cargo

**Q49. package、crate、module 的关系？**
package（一个 `Cargo.toml`）含一个或多个 crate；crate 是编译单元（lib/bin）；module 是 crate 内的命名空间（`mod`，可拆文件）。

**Q50. `Cargo.lock` 要提交吗？**
二进制/应用项目应提交（锁定可复现构建）；库项目传统上不提交（由下游解析），但现代实践两种都可接受。

**Q51. workspace 的用处？**
多 crate 共享 `Cargo.lock`、`target/` 与统一依赖版本，便于大型项目拆分与增量编译。

**Q52. features 是什么？default-features=false 的意义？**
条件编译/可选依赖开关。关闭默认 features 可裁剪依赖、减小体积、避免引入不需要的功能（如 `no_std` 场景）。

## 十、底层 / unsafe / 宏

**Q53. `unsafe` 允许哪几件事？它会关闭借用检查吗？**
允许：解引用裸指针、调用 unsafe 函数、访问/修改可变静态变量、实现 unsafe trait、访问 union 字段。它**不会**关闭借用检查，安全责任由程序员承担。

**Q54. 声明式宏与过程宏的区别？**
`macro_rules!` 声明式（模式匹配生成代码，如 `vec!`）；过程宏（`proc_macro`）分 derive/属性/函数式三类，接收 token 流做变换（如 `#[derive(Serialize)]`）。

**Q55. `PhantomData<T>` 有什么用？**
在类型中标记「逻辑上拥有/关联 T」但不实际存储，用于泛型参数占位、变型（variance）控制与 drop check。

## 十一、代码题（能否编译 / 输出）

**题 1：以下代码能编译吗？**
```rust
let s1 = String::from("hi");
let s2 = s1;
println!("{s1}");
```
**答**：不能。`s1` 的所有权已 move 给 `s2`，再用 `s1` 报 `borrow of moved value`。想保留用 `s1.clone()`。

**题 2：能编译吗？**
```rust
let mut v = vec![1, 2, 3];
let first = &v[0];
v.push(4);
println!("{first}");
```
**答**：不能。`first` 是不可变借用，`v.push` 需要可变借用，二者在 `first` 使用前冲突。

**题 3：输出什么？**
```rust
fn main() {
    let s = String::from("hello");
    let r = &s;
    println!("{r}");
}
```
**答**：输出 `hello`；借用在使用后即结束，合法。

**题 4：能编译吗？**
```rust
fn longest(x: &str, y: &str) -> &str { if x.len() > y.len() { x } else { y } }
```
**答**：不能。多个输入生命周期时返回引用需要标注：`fn longest<'a>(x: &'a str, y: &'a str) -> &'a str`。

**题 5：能编译吗？**
```rust
let x = 5;
let y = &x;
let z = &mut x;
```
**答**：不能。`x` 不是 `mut`，且已存在不可变借用 `y` 时不能再取可变借用。

**题 6：输出什么？**
```rust
let v = vec![1, 2, 3];
let sum: i32 = v.iter().map(|x| x * 2).sum();
println!("{sum}");
```
**答**：输出 `12`（1*2 + 2*2 + 3*2）。`v` 未被消耗（`iter()` 借用）。

**题 7：能编译吗？**
```rust
use std::rc::Rc;
use std::thread;
let data = Rc::new(5);
thread::spawn(move || println!("{data}"));
```
**答**：不能。`Rc` 非 `Send`，不能跨线程；改用 `Arc`。
