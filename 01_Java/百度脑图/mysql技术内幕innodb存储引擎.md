# mysql技术内幕innodb存储引擎

- mysql体系结构和存储引擎
  - 定义数据库和实例
    - 数据库
      - 物理操作系统文件或其他形式文件类型的集合。mysql中数据库文件可以是frm，myd，myi，ibd结尾的文件。当使用ndb引擎时，数据库的文件可不是操作系统上的文件，而是存放于内存之中的文件，但是定义仍不变
    - 实例
      - 数据库实由数据库后台进程/线程以及一个共享内存组成的。共享内存可以被运行的文件后台进程/线程所共享。需要牢记的是，数据库实例才是真正用来操作数据库文件的。
      - 数据库和实例一一对应，在集群情况下可能存在一个数据库可被多个实例使用的情况
    - mysql读取配置文件顺序：/etc/my.cnf /etc/mysql/my.cnf /usr/local/mysql/etc/my.cnf ~/.my.cnf

  - mysql表存储引擎
    - innodb
      - 支持师傅主要面向在线事务处理方面应用。其特点是性锁设计，支持外键，支持类似非锁读，默认的引擎。innodb春芳在一个逻辑表空间中，这个表空间像黑盒一样有innodb自身4.1开始它可以将每个innodb存储硬气表单独存放到一个独立的ibd文件。
    - MYISAM存储引擎
      - 官方提供引擎不支持事务，表锁和全文索引
    - NDB存储引擎
      - NDB存储引擎时一个集群存储引擎，特点是数据全部存放内存中（5.1开始可以将非索引放到磁盘上），问题NDB存储连接JOIN在数据库层延迟复杂操作巨大网络开销查询速度慢
    - Memory存储引擎
      - 数据在内存重启数据会丢失用哈希索引，速度快只支持表锁，并发性能差
    - Archive存储引擎
      - 只支持插入和查询 不是事务安全的存储引擎，设计目的主要提供高速的插入和压缩功能
    - Federated存储引擎
      - 不存放数据，指向一台远程mysql数据库服务器上的表不支持异构数据库表
    - maria存储引擎
      - MYISAM延续特点缓存数据和索引文件，行索引设计，提供mvcc功能，支持事务，和非事务安全支持
    - 其他引擎
      - 当表数据大于1000w时，mysql的性能会急剧下降吗，不是 需要选择正确的存储引擎，

- innodb存储引擎
  - innodb存储引擎概述
    - 一些网站上存超过1TB数据，一些站点每秒插入800次操作
  - innodb体系架构
    - 后台线程
    - 内存
      - 缓冲池
        - 配置文件 innodb_buffer_pool_size
        - 占最大块内存部分，用来存放各种数据的缓存，因为innodb的存储引擎的工作方式总是讲数据库文件按页（16k）读到缓存池，按照最少使用算法保留在缓冲池中的缓存数据，缓冲页更改按照一定频率将缓冲池刷新到文件 free buffers 空闲缓存帧
        - 命令 ： show engine innodb status;
      - 重做日志缓冲池
        - 配置文件innodb_log_buffer_size
        - 每秒产生的事务量在这个大小即可
      - 额外的内存池
        - 配置文件 innodb_additional_mem_pool_size
        - 该内存不够时会从缓冲池中申请，缓存池很大的时候这个值应该增加
