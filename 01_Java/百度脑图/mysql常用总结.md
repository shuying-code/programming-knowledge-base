# mysql常用总结

- innodb引擎支持事务行锁，支持类似非锁读，myisam存储引擎，不支持事务 表锁和索引，NDB 集群索引，join 在数据库层查询速度慢
- mysql 的缓冲池 重做日志缓冲池 额外缓冲池 需要合理分配内存
- master thread 后台线程在多cpu下合理配比
- 开启慢查询日志，开启sql语句不命中索引日志 开启binlog日志
- 分区表能提升io 一般用 range分区类型
- innodb 用的是b+算法 聚集索引也就是每张表的主键构成的一个b+树 注意聚集索引在存储上并不是物理上的联系而是逻辑上的连续 辅助索引 相对来说比聚集索引多一倍逻辑io访问一个数据页
- 数据库事务xa 也可以用于分布式事务
- 事务的隔离级别：脏读，不可重复读，幻读 加锁读 事务遵循ACID特性，原子性，一致性，隔离性，持久性
- 选适合是cpu，内存的重要性 当缓存池大于数据和索引时tps会达到最快 硬盘和操作系统啊，以及mysql在liunx下出现区分大小写和win下不区分大小写
- sql执行计划查看是否命中索引，以及缩小结果集
- 误区一索引层不要超过5层 b+ 一亿条数据 占用空间会从磁盘读而不是从缓冲池中读
- 误区二索引树不要超过6个 具体规范听dba的
- 误区二不索引不稳定的列 怕磁盘驱动器负载
- 数据结构设计要小，简单就好，避免为null除非真为null 范式和反范式混合用
